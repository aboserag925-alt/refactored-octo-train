# abu-seraj-orchestrator-cjs

محرك أبو سراج (Orchestrator) بنمط CommonJS، في ملف واحد: `abu-seraj-all-in-one.js`.

يحتوي الملف على:
- `contracts`: حالات المحرك (ORCHESTRATOR_STATES) ومستويات الخطر (RISK_LEVELS) ووظائف التحقف والـ handoff
- `RiskGate` و`StateHandoff` و`RecoveryRouter`: تقييم الخطر وتطبيع المخرجات وتوجيه الحالات
- `SkillRegistry` و`SkillDiscovery`: تسجيل المهارات واكتشافها بالنقاط
- `SkillTaskAdapter`: تنفيذ مهارة عبر agentLoop مع بوابة موافقة قبل أي خطر غير قراءة (يشمل write). الموافقة كائن مربوط باسم المهارة ومعطياتها، ينتهي، ويُستهلك مرة واحدة (`issueApproval`). علم `approved` العام لم يعد يعمل
- `LocationResolverSkill`: طلب إذن الموقع وفتح خرائط جوجل

## التشغيل

المحرك بلا أي مكتبات خارجية، يعمل على Node.js 20 أو أحدث. `js-yaml` اختياري داخل `loadAll` فقط (يُستخدم `safeLoad` أو `load` من الإصدار 4)، ويمكن تمرير `yamlParser` بديل. المانيفست المرفوض يُسجَّل في `registry.errors` ولا يُحمَّل.

## مستويات الخطر

كل المستويات عدا `read-only` تحتاج NEED_APPROVAL، ومنها `external-communication` (واتساب وتيليجرام وجيميل، إرسالًا وقراءة). أي مستوى مجهول أو غائب يفشل مغلقًا. مانيفست بلا risk يُعامل كـ write. سجل المخاطر المركزي (`riskRegistry`) يرفع الخطر فقط ولا يخفضه.

## ما لم يُنفَّذ بعد

ربط الموافقة بنص الرسالة والمستلم للقنوات الخارجية، وتتبع taint على مستوى الجلسة، تسبقان أي ربط فعلي بقنوات الإرسال. الموافقات المستهلكة تُحفظ في الذاكرة فقط.

## الاختبارات

```bash
node --test abu-seraj-orchestrator-cjs/test/orchestrator.test.js
```

الاختبارات تغطي السلوك الفعلي: عقود الحالات، كل مستويات الخطر، توجيه الاسترداد، التسجيل والاكتشاف، تنفيذ المهارات مع الموافقات، ومهارة الموقع.
